Mi a hibakezelés és az aszinkronitás kapcsolata Node.js esetén?

A hibakezelés (Error Handling) és az aszinkronitás szorosan összefügg a Node.js-ben. Mivel az aszinkron műveletek nem azonnal, hanem később fejeződnek be, a hibák sem mindig ott jelentkeznek, ahol a műveletet elindítottuk. Emiatt az aszinkron kódban más hibakezelési technikákat kell alkalmazni, mint a szinkron kódban.

A Node.js-ben az aszinkron hibakezelés három fő módja terjedt el:

  1. Callback alapú hibakezelés
  2. Promise alapú hibakezelés
  3. async / await + try...catch

Miért különleges az aszinkron hibakezelés?

Szinkron kódban a hiba azonnal keletkezik.

console.log('Start');

throw new Error('Hiba!');

console.log('Vége');

A program megszakad a throw utasításnál.

Aszinkron kódban viszont:

fs.readFile('hello.txt', callback);

a readFile() azonnal visszatér, a hiba pedig csak később derülhet ki.

1. Callback alapú hibakezelés

A klasszikus Node.js API-k többsége az úgynevezett error-first callback mintát használja.

A callback első paramétere mindig a hiba.

import fs from 'node:fs';

fs.readFile('nemletezik.txt', 'utf8', (err, data) => {
    if (err) {
        console.error(err.message);
        return;
    }

    console.log(data);
});

Kimenet:

ENOENT: no such file or directory...

Miért kell az if (err)?

Ha nincs hiba:

err === null;

Ha hiba történt:

err instanceof Error;

Ezért mindig:

if (err) {
    // hiba kezelése
}

2. Promise alapú hibakezelés

A modern Node.js modulok Promise-t adnak vissza.

import fs from 'node:fs/promises';

fs.readFile('nemletezik.txt', 'utf8')

    .then((data) => {
        console.log(data);
    })

    .catch((err) => {
        console.error(err.message);
    });

A .catch() csak akkor fut le, ha a Promise Rejected állapotba kerül.

3. async / await hibakezelés

A legmodernebb megoldás:

import fs from 'node:fs/promises';

async function main() {
    try {
        const text = await fs.readFile('nemletezik.txt', 'utf8');

        console.log(text);
    } catch (err) {
        console.error(err.message);
    }
}

main();

Ez nagyon hasonlít a szinkron kód hibakezeléséhez.

Miért kell a try...catch?

Ha nincs:

await fs.readFile('nemletezik.txt');

akkor a Promise elutasítása kezeletlen maradhat.

A try...catch elkapja az ilyen hibákat.

Saját Promise hibával

function letoltes() {
    return new Promise((resolve, reject) => {
        reject(new Error('Letöltési hiba.'));
    });
}

letoltes().catch((err) => {
    console.log(err.message);
});

Kimenet:

Letöltési hiba.

Saját async függvény

async function osztas(a, b) {
    if (b === 0) {
        throw new Error('Nullával nem lehet osztani.');
    }

    return a / b;
}

async function main() {
    try {
        console.log(await osztas(10, 2));

        console.log(await osztas(10, 0));
    } catch (err) {
        console.log(err.message);
    }
}

main();

Helyes callback hibakezelés

fs.readFile('hello.txt', (err, data) => {
    if (err) {
        console.log(err.message);
        return;
    }

    console.log(data);
});

Helyes async hibakezelés

try {
    const data = await fs.readFile('hello.txt');
} catch (err) {
    console.log(err.message);
}

Hibakezelés HTTP szervernél

import http from 'node:http';

const server = http.createServer(async (req, res) => {
    try {
        throw new Error('Valami hiba.');
    } catch {
        res.statusCode = 500;

        res.end('Szerverhiba');
    }
});

server.listen(3000);

A kliens nem a kivételt látja, hanem egy megfelelő HTTP hibaválaszt.

Összefoglalás

A hibakezelés és az aszinkronitás elválaszthatatlanul összetartozik a Node.js-ben. Mivel az aszinkron műveletek később fejeződnek be, a hibák sem ott jelentkeznek, ahol a művelet elindult. Ezért a hibák kezelését mindig az adott aszinkron modellhez kell igazítani: callbackeknél az error-first callback (if (err)), Promise-oknál a .catch(), míg async/await használatakor a try...catch a megfelelő megoldás.

A modern Node.js fejlesztésben az async/await és a try...catch együttes használata a leginkább ajánlott, mert jól olvasható, könnyen karbantartható és a szinkron kódhoz hasonló hibakezelési mintát biztosít. Emellett fontos megjegyezni, hogy a szinkron try...catch nem fogja elkapni a callback-alapú aszinkron műveletekben később keletkező hibákat, ezért mindig az adott aszinkron mechanizmusnak megfelelő hibakezelést kell alkalmazni.
