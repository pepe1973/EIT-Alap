Mit értünk event loop-on Node.js esetén és mi a kapcsolata az eseményekkel?

Az Event Loop (eseményciklus) a Node.js futtatókörnyezetének központi mechanizmusa, amely folyamatosan figyeli az eseményeket (events) és az aszinkron műveletek befejeződését, majd a megfelelő időben végrehajtja a hozzájuk tartozó kódot.

Egyszerűen megfogalmazva:

Az esemény (event) azt jelzi, hogy valami történt, az Event Loop pedig gondoskodik arról, hogy az eseményhez tartozó eseménykezelő (event listener vagy callback) megfelelő időben lefusson.

Az Event Loop és az események tehát szorosan összetartoznak.

Az esemény és az Event Loop kapcsolata

Képzeljük el egy étterem működését:

  • Az esemény az, hogy egy vendég rendel.
  • Az Event Loop a pincér.
  • Az eseménykezelő pedig a szakács, aki elkészíti az ételt.
Vendég rendel
      │
      ▼
Esemény keletkezik
      │
      ▼
Event Loop észleli
      │
      ▼
Meghívja az eseménykezelőt
      │
      ▼
A megfelelő kód lefut

Mi az esemény?

Az esemény egy olyan jelzés, hogy valami megtörtént.

Például:

  • HTTP kérés érkezett.
  • Elkészült egy fájl olvasása.
  • Lejárt egy időzítő.
  • Hiba történt.
  • TCP kapcsolat létrejött.
  • Egy stream új adatot kapott.

Mi az Event Loop?

Az Event Loop egy folyamatos ciklus.

while (a program fut) {

    eseményeket figyel;

    ha van végrehajtható callback {

        végrehajtja;

    }

}

Természetesen a Node.js belső működése ennél jóval összetettebb, de az alapelv ez.

Példa 1 – Egyszerű esemény

import { EventEmitter } from 'node:events';

const emitter = new EventEmitter();

emitter.on('hello', () => {
    console.log('Hello!');
});

emitter.emit('hello');

A Call Stack szerepe

Az Event Loop csak akkor tud új callbacket futtatni, ha a Call Stack üres.

Példa:

console.log('A');

setTimeout(() => {
    console.log('B');
}, 0);

console.log('C');

Kimenet:

A
C
B

A setTimeout(..., 0) nem azt jelenti, hogy a callback azonnal lefut, hanem azt, hogy legkorábban akkor hajtható végre, amikor:

  • letelt a megadott idő,
  • és a Call Stack már üres.

Az Event Loop főbb fázisai

A Node.js Event Loop több fázison halad végig.

┌──────────────────────┐
│ Timers               │
├──────────────────────┤
│ Pending Callbacks    │
├──────────────────────┤
│ Poll                 │
├──────────────────────┤
│ Check                │
├──────────────────────┤
│ Close Callbacks      │
└──────────────────────┘

A legfontosabbak:

Fázis Kezelt események
Timers setTimeout(), setInterval()
Poll fájlműveletek, hálózati I/O
Check setImmediate()
Close Callbacks kapcsolatok lezárása

Mi történik egyszerre több eseménynél?

console.log('Start');

setTimeout(() => {
    console.log('Timer');
}, 100);

setImmediate(() => {
    console.log('Immediate');
});

console.log('End');

A "Start" és "End" mindig előbb jelenik meg. Az, hogy a setImmediate() vagy a setTimeout() callbackje fut-e le előbb, bizonyos helyzetekben a futtatási környezettől és attól függ, hogy a hívások melyik Event Loop fázisban történtek. Például egy I/O callbacken belül a setImmediate() jellemzően megelőzi a setTimeout(..., 0) callbackjét.

Miért fontos az Event Loop?

Ennek köszönhetően a Node.js:

  • egyszerre több ezer hálózati kapcsolatot képes kezelni;
  • nem blokkolódik fájlműveletek közben;
  • jól skálázható webszervereket tesz lehetővé;
  • hatékonyan használja a memóriát és a CPU-t I/O-intenzív feladatoknál.

Mikor akad meg?

Ha hosszú ideig futó, CPU-igényes JavaScript kód fut:

while (true) {}

akkor:

Call Stack
      │
      ▼
soha nem ürül ki
      │
      ▼
Event Loop nem tud dolgozni
      │
      ▼
Minden esemény várakozik

Ezért az ilyen feladatokat célszerű külön Worker Thread vagy külön folyamat segítségével végrehajtani.

Összefoglalás

Az esemény (event) a Node.js-ben egy jelzés arról, hogy egy művelet vagy állapotváltozás bekövetkezett, például egy fájl beolvasása befejeződött, HTTP kérés érkezett vagy lejárt egy időzítő. Az Event Loop az a mechanizmus, amely folyamatosan figyeli ezeket az eseményeket és az aszinkron műveletek eredményét, majd amikor a JavaScript végrehajtási verem (Call Stack) szabaddá válik, végrehajtja a hozzájuk tartozó callback függvényeket.

Az események és az Event Loop együtt alkotják a Node.js eseményvezérelt működésének alapját. Az események jelzik, hogy valami történt, az Event Loop pedig biztosítja, hogy a megfelelő eseménykezelők a megfelelő időben fussanak le. Ennek köszönhetően a Node.js egyetlen JavaScript szál használata mellett is képes nagyszámú egyidejű I/O műveletet és hálózati kapcsolatot hatékonyan kezelni.
